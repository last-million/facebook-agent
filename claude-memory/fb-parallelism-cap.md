**THE CAP IS CPU-BOUND (server.js `computeMachineParallelCap` ~8088):** `usableCores=(cores-2 OS)*(1-0.25 Pinterest)=5.25; byCpu=floor(usableCores/CORES_PER_PROFILE); byRam=floor((totalGB-4)/1.5); cap=min(HARD_CEILING 8, byCpu, byRam)`. On this box byRam=18 (non-binding) — **CPU is the limit**. CHANGED **CORES_PER_PROFILE 1.5 -> 1.0 => cap 3 -> 5** (commit 726021d). The 1.5 was the operator's own post-incident value (2026-06-15 cap-5 pegged CPU 99-100% -> unresponsive -> watchdog killed it 4x); 1.0 is safe NOW because the live breaker that wasn't biting then is in place. Measured per-profile cost is ~0.7 cores (the 1.5 model was 2x pessimistic); cap 5 projects ~40% CPU / ~50 chrome — huge margin. Also raised **GLOBAL_MAX_OPEN_PROFILES 8 -> 14** (server.js ~80; so 5 posters + their commenters don't starve on the cap) and **waitForCpuHeadroom maxChrome default 220 -> 150** (the old 220 sat ABOVE the ~201-chrome crash point — couldn't fire in time).

**`maxConcurrentProfiles` (the worker count the operator actually runs) is CLAMPED to `machineParallelCap` on every write (normalizeWorkflowState ~1674) and re-clamped at dispatch (~9079). It does NOT auto-rise when the cap rises — must be SET.** After the restart (boot recomputes machineParallelCap=5, capMeta `{cores:9,totalGB:32,byCpu:5,byRam:18}`), did PUT `{state:{ixbrowser:{maxConcurrentProfiles:5}}}` -> now 5. PROFILES ARE NOT THE BOTTLENECK: ixBrowser `profile-list` returns **49 profiles** (NOT the stale ~4 in [[fb-agent-highscale-pipeline]] = 8,10,12,19), so cap 5 is fully usable.

**THE "NEVER CRASH" SAFETY STACK (adversarially verified wkaq1n1oc — merged verdict SAFE; the machine cannot OOM/hard-crash at cap 5 + GLOBAL 14):**
1. **OOM is fully closed** — EVERY concurrent open (posting 15042, harvest 8493, discovery/`captureIxBrowserPage` 7169, admin-approval 12290, comment-recovery 12916, pin-recovery, URL-recovery) funnels through `acquireNormalIxProfileUse` which throws a typed retryable 503 at `normalIxProfileUseLocks.size >= 14`. So total concurrent opens <=14 (~<=112 chrome / ~18GB) << the ~30-50-profile / 201-chrome RAM crash. The 15th open defers.
